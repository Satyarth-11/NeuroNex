FIX 3 (P1): High-frequency communication detector — small-sample robustness
============================================================
FILE: backend/app/pipeline/patterns.py, function detect_high_frequency_communication()

Replace the unconditional 95th-percentile logic with sample-size-aware logic:
    n = len(weights)
    if n < 10:
        # Too few observations for a meaningful percentile — use an honest minimum-
        # threshold approach instead: flag only pairs with weight >= 3x the dataset
        # mean AND weight >= 5 (an absolute floor so single high-weight edges in a
        # near-empty dataset aren't over-flagged).
        mean_w = sum(weights) / n if n else 0
        threshold = max(5, round(mean_w * 3))
        basis = f"absolute-threshold (dataset too small for percentile analysis, n={n})"
    else:
        weights_sorted = sorted(weights)
        cutoff_idx = max(0, int(n * 0.95) - 1)
        threshold = weights_sorted[cutoff_idx]
        basis = f"95th-percentile (n={n} communication edges)"

For every flagged pattern, add these fields to the returned dict:
    "sample_size": n,
    "threshold_used": threshold,
    "comparison_basis": basis,
And change the description template to explicitly state the basis, e.g.:
    f"Communication frequency ({w} contacts) is unusually high relative to the "
    f"{n} communication records available in this dataset ({basis}). "
    f"Potential anomaly, requires analyst review."
Never say "highly suspicious" or imply the result is statistically robust when n < 10 —
the description must make the small-sample caveat visible to the reader, not just log it.

MODIFY: frontend/src/pages/Insights.jsx and any pattern-detail rendering — display
sample_size and comparison_basis alongside the pattern description so an analyst can see
the statistical basis, not just the conclusion.
